# 开发 Skill 与文档模板验证

> 本报告记录执行当时的版本与验证范围；当前能力及后续记录见 [验证索引](README.md)。不将旧统计或未验证项改写为本轮通过。

本记录为初版五模板的历史证据。当前已改为简版一份/完整版三份，见 [最新精简验证](adaptive-development-skill.md)；下文保留原始验证范围。

## 实现范围

开发角色已连接 [feature-development](../../skills/feature-development/SKILL.md)。阶段详细规则迁入 Skill 参考文件，原 workflow/development.md 作为兼容入口。Skill 提供普通执行与长任务恢复指引，以及五份真实模板：技术方案、模块/任务计划、检查点、改动清单和完整自验。

模板先读后实例化，输出到当前 run；已有文稿保留内容与历史证据。源模板和框架状态不由执行角色改写。结果仍复用公共 role-result 契约，artifacts 明确为 kind/path 对象。

## 基线与隔离执行

独立基线评估指出：原有任务/结果 YAML 模板可用，但开发文稿仅有产物名称，没有具体模板入口或检查点结构。本轮补齐这些资源。

两名独立子 Agent 实际读取开发角色、Skill 及模板，在不同临时目录执行离线合成任务：

| 场景 | 实际结果 |
| --- | --- |
| 正常开发 | 先生成技术方案与普通模块计划，再实现运费规则；阈值、负数异常、真实结算调用、整数回归及编译检查通过，返回 ready。 |
| 长任务恢复夹具 | 保留原计划和检查点；因旧记录无可靠摘要重新核对源码、模块与集成证据。局部检查通过，但预设必需整体检查失败，返回 blocked；未绕过失败或修改只读源码。 |

复核中发现公共结果模板对 artifacts 项结构不够明确，正常场景最初返回字符串列表。补充 kind/path 契约后，原 Agent 通过一次跟进修正结果文件，未重复业务检查。恢复场景按更新契约返回。

证据：[检查记录](evidence/development-skill-2026-10-15/checks.json)、[正常结果](evidence/development-skill-2026-10-15/normal/feature/revisions/v1/runs/run-check/outputs/result.yaml)、[恢复结果](evidence/development-skill-2026-10-15/resume/feature/revisions/v1/runs/run-check/outputs/result.yaml)。

## 核对结果

- Skill 官方 quick_validate 校验通过。
- 分享核心包含 skills/，复制到带空格的新目录后，73 个本地文档链接全部可解析，无作者固定路径，YAML 可解析。
- 两个任务的必需文稿均非空、无未替换模板占位符，结果身份及源码摘要一致；产物路径在当前输出内。
- 当前 task、需求及根状态保持不变，恢复夹具的只读源码保持不变，模板源摘要保持不变，旧计划与检查点原文保留。

## 边界

approval 是明确标记的合成测试数据，不是真人批准。真实子 Agent 调用用于验证开发角色和 Skill，不经过完整协调派发流程。恢复场景使用预置历史，不是真实跨会话崩溃注入；离线错误由夹具脚本模拟，并未访问外部服务。

本轮不证明宿主原生注册/Skill 自动发现已可用，也不证明完整产品、审批、开发、测试闭环、飞书或其他宿主已通过。产品与测试入口 Skill 仍待搭建。历史证据保留原始临时路径，只用于追溯，不随核心分享包安装。
