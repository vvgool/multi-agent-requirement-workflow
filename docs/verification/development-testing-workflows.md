# 开发与测试流程补充：规则走查

> 本报告记录执行当时的版本与验证范围；当前能力及后续记录见 [验证索引](README.md)。不将旧统计或未验证项改写为本轮通过。

> 历史静态走查记录：下文“未搭建入口 Skill”描述当时状态；后续验证见 [开发](adaptive-development-skill.md) 与 [测试](acceptance-testing-skill.md)。

本记录只说明文档与契约检查，不是业务功能或宿主执行测试。

| 场景 | 应有结果 |
| --- | --- |
| 模块 B 依赖 A | 明确排序及依赖；A 验证通过后推进 B |
| 一个需求含简单模块与复杂模块 | 每模块独立选择普通/长任务，记录依据，不将整个需求一律判为长任务 |
| 所有模块各自通过，整合流程失败 | 开发继续修复或阻塞，不返回 ready |
| 长任务中断，代码发生变化 | 读取检查点及真实代码，重验受影响项再继续 |
| 实现漏掉已批准规则，而既有用例未覆盖 | 测试补齐用例并验证偏离，确认缺陷后 failed |
| 用例预期迁就实现，偏离需求 | 修正用例预期并重测，不通过修改需求消除差异 |
| 技术实现不同于原方案，但仍满足业务与接口约束 | 记录调整依据并验证影响，不自动判失败 |
| 测试证据来自旧开发基线 | 阻塞核对，不能 passed |
