# 阶段流程

## 1. 分析与方案

读取相关代码、规则、批准需求和缺陷报告，选择文档档位，记录实现方式、影响和验证方法。简版写入 development.md，完整版写入 technical-plan.md。需求/验收编号引用原文即可；业务语义或范围变化交协调层。

## 2. 模块、任务与顺序

复杂需求按可交付能力拆独立可验证大模块，明确输入输出及依赖，解决循环后排定顺序；再为模块拆可验证小任务，指定修改目标、前置条件、检查和完成标准。

简版可将单模块与小任务合并成简短执行列表。完整版在 implementation-plan.md 展开模块及任务。都要覆盖全部验收，给出适用的集成和整体验证方法。

## 3. 逐模块选择模式并执行

根据任务复杂度、依赖、影响、验证成本和恢复需求，为模块选择普通或长任务，说明理由。简版也可有长任务；不根据文档档位一刀切。

按模块依赖及小任务顺序实施，任务与模块验证通过后再推进相关下游。计划记录进度及证据引用，检查结果只写一处；失败先修复，无法继续则报告阻塞。计划调整保留原因，业务范围变化重新确认。

## 4. 完整自验与交付

模块完成后验证完整需求、实际集成及适用异常/回归。同一检查已覆盖任务、模块和完整行为时引用同一证据，无需为层级重复执行。

在简版开发记录或完整版自验报告中记录验收项、实际结果、证据、变更摘要和遗留限制。必需检查失败或未执行不能 ready；无关平台检查不必机械列为门禁。

代码修改导致旧证据失效时重验受影响范围，再生成与实际已验证实现一致的最终基线。结果使用公共 result.yaml，交付按档位选择的一份或三份文档及实际证据；额外报告只在项目规则或实际复杂度需要时生成。
