# 全阶段协调规则核对

> 本报告记录执行当时的版本与验证范围；当前能力及后续记录见 [验证索引](README.md)。不将旧统计或未验证项改写为本轮通过。

> 历史规则走查记录：下文角色缺失及独立 quality-check.md 是当时状态。当前产品自检默认合并文稿，三个执行角色均有 Skill；当前能力见 [README](../../README.md)。

问题：此前协调角色实际只调用产品，批准后固定停止，缺少开发、测试及失败回退的角色分支。

本轮将协调角色改为统一按阶段选角色、检查可用性、派发、校验结果、转阶段并继续选择下一步。完整契约见 [routing.md](../../workflow/routing.md)；新增开发/测试公共任务和结果模板，不新增 CLI，也未代替实现两个执行角色。

## 规则走查

| 输入条件 | 已写明的动作 |
| --- | --- |
| draft，产品角色可用 | 读取输入、派发产品，检查 ready/needs_input/blocked。 |
| requirement_review，未明确批准 | 保持等待，不派发开发。 |
| 当前版本获明确批准 | 进入 development，检查开发角色，不再固定按阶段停止。 |
| 开发角色缺失 | development/blocked，role_not_available，不消耗开发次数。 |
| 开发 ready 且方案/改动/验证/基线通过检查 | 进入 testing，检查并派发测试角色。 |
| 测试 passed 但有未执行项或基线不符 | 不接受为完成，阻塞并记录缺项。 |
| 测试 passed 且全部验收证据通过 | completed，归档证据，不发布。 |
| 测试 failed，仍有开发次数 | 保存可复现缺陷，回到 development，修复任务必读该报告。 |
| 测试 failed，次数用完 | development/blocked，development_attempt_limit。 |
| 测试 blocked | 留在 testing，环境或证据问题不冒记通过、不无依据当作代码缺陷。 |
| 旧版本或旧开发基线结果 | 不推进当前状态，不清除新任务。 |
| 恢复旧版硬编码开发阻塞 | 重新核对角色实际可用性，保留有效审批，不无条件解除或永久停止。 |

## 检查结果与边界

### 状态优先入口补充走查

首次接单、恢复、用户答复和角色返回均重新读取 status.yaml，以持久化状态选择唯一动作。协调文件的派发、结果处理和产品评审已加条件入口，不能将章节顺序当作固定执行顺序。

| 状态场景 | 规则核对结果 |
| --- | --- |
| development/idle 且 active_run 非空 | 先核查已有任务，不重复派发。 |
| testing/waiting_user | 展示当前问题，处理对应答复后仍按 testing 决策，不重跑产品。 |
| development/blocked，用户仅说继续 | 检查原阻塞解除条件，不能直接清除。 |
| requirement_review 收到明确批准 | 核验本版内容和审批后进入 development；已保存有效审批但迁移中断时可补完迁移。 |
| 开发或测试结果返回 | 校验结果后回到状态入口，不进入产品评审文稿生成步骤。 |
| 已有需求状态缺失、未知或矛盾 | 阻塞核查，不默认初始化 draft。 |
| completed | 展示已有证据；优化按修订规则创建新版。 |

以上为规则和分支静态走查，未执行真实开发/测试任务或恢复故障注入。状态决策需记录所读状态版本、阶段、执行状态、动作和原因。

已核对：协调文件包含三类结果处理与全阶段路由；公共任务/结果身份字段匹配；YAML 模板可解析；核心文档 43 个本地链接有效，未引入作者机器路径。

实际文件检查：product-agent.md 存在，development-agent.md 与 testing-agent.md 不存在。因此当前真实可运行链路仍限于产品阶段；全阶段路由是 Agent 的执行规则，不是已经发生过的开发/测试调用。本轮未进行真人审批、开发/测试真实派发或缺陷修复循环验证。早前 4 次产品调用只证明原产品闭环，不作为本次完整流程实测证据。


## 职责精简后的当前规则（2026-10-15）

本节替代上文对当前职责和角色可用性的描述；上文保留为先前走查记录。

- 协调角色收敛为读取状态、派发、接收结果及更新状态，只核对交接身份、版本、产物和基线完整性。

本轮检查为核心文档链接、模板解析、职责边界及迁移分支静态核对。历史产品调用不证明本轮精简后流程已通过；没有新增真实角色调用、真人审批、飞书读写或开发/测试闭环验证。
