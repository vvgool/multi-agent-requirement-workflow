# 精简文档与项目开发原则验证

> 本报告记录执行当时的版本与验证范围；当前能力及后续记录见 [验证索引](README.md)。不将旧统计或未验证项改写为本轮通过。

> 历史隔离验证记录：文末产品/测试 Skill 缺失是当时状态；后续已分别实现并隔离验证，见 [产品](requirement-analysis-skill.md) 与 [测试](acceptance-testing-skill.md)。真实宿主与完整闭环仍待验证。

## 当前规则

开发 Skill 改为两档真实模板：小需求使用一份 development.md；复杂或高风险需求使用技术方案、执行计划、自验三份文档。四份源模板分别为 25、11、21、13 行，只生成当前需要的一组。结果仍用公共 result.yaml，日志与可复现脚本按实际验证需要保留。

独立改动清单模板已移除，变更并入交付记录；独立检查点模板已移除，恢复信息默认并入计划。旧文稿和历史检查点按原索引读取，不批量删除。文档档位与模块执行模式分别判断，质量门槛不变。

开发原则先查目标项目规则、架构约定及工具配置；缺少约定时使用 Clean Architecture 的职责与依赖方向，按当前改动规模做最小设计，避免无关迁移或机械分层。测试按实际内容及产物索引读取，简版缺少完整版文件名不构成阻塞。

## 隔离行为验证

三个独立子 Agent 读取当前角色规则，在互相隔离的合成工作空间实际执行：

| 场景 | 观察结果 |
| --- | --- |
| 局部低风险开发，已有项目规则 | 选择简版和普通执行，遵循 project/AGENTS.md 保留平铺结构，仅修改业务函数；实际边界、负数异常和结算集成通过，ready。仅生成一份 Markdown 开发记录。 |
| 高风险集成恢复，无架构约定 | 选择完整版，记录默认 Clean 原则和不增加抽象的依据；模块分别使用长任务和普通执行，保留旧计划/检查点。局部重验通过，但注入的必需集成检查失败，blocked。当前交付为三份 Markdown。 |
| 测试消费简版开发交付 | 从一份 development.md 读取方案、任务和自验，独立执行真实调用检查及需求偏离核对，passed；用例、偏离和结果合并为一份 test-report.md。 |

恢复场景首次将实际执行结果追加到末尾，表格仍保留将来时进度。补强就地更新约定后，通过一次跟进更新当前任务/模块表；历史原文保持，未重复业务检查。

结果与复核见 [checks.json](evidence/adaptive-development-2026-10-15/checks.json)，其中记录实际 Agent 标识和各场景产物。

## 完整性与边界

源码摘要与结果基线一致；要求只读的需求、任务、根状态、项目规则、开发产物与原始检查均保持不变；真实模板源未被执行角色改写，输出无未替换占位符。Skill 校验、YAML 解析及共享副本 68 个本地链接通过，无作者固定路径。

本轮 approval 是显式标记的合成数据；恢复使用预置记录，集成离线由夹具脚本模拟。测试消费验证没有通过协调层自动串联，不代表完整业务闭环或真实外部计费网关通过。宿主原生注册、实际中断恢复及产品/测试入口 Skill 仍未验证或未实现。
