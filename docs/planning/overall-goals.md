# 整体目标与演进路线（v1.0 / 协议 4）

让用户在 Codex、Claude Code、OpenCode 或 Zed 中直接表达业务目标，以**第一性原理直击本质、快速解决根本问题、长时间连续执行不偏离目标、最少打断用户**。

## 协议 4 轻内核的核心取舍

| 核心痛点 | 协议 4 解决方案 | 约束机制 |
| --- | --- | --- |
| 顺从伪需求与叠打治标补丁 | 第一性原理贯穿需求、设计与排障全链 | 需求穿透 XY 表象追问根本矛盾与硬约束；设计“先删减、再下沉脚本/代码、后新增”；排障回到数据流与不变量推导根因 |
| 规则膨胀与注意力稀释 | 运行包收敛至 ≤ 60 文件（≤ 160 KiB），常驻受管入口 ≤ 60 行 | 清除旧协议桩文件、机器 YAML 模板与跨文件重复免责声明 |
| 日常会话启动与派发慢 | 安装/升级/恢复期由 `install_helper.py` 一次性校验 SHA256 | 日常本地缓存存在时零哈希重算、零回执查询开销 |
| 小修仪式重 vs 大需求乱改 | 四档自适应分流 + 显式阶段状态机（两道 `<HARD-GATE>`） | 小修零文档直通；复杂事项先代码取证合并提问，两批确认后动代码 |
| 长任务易偏航与频繁打断 | `ready_to_implement` 静音连续巡航 + 3 类真阻塞打断白名单 | 单元只读回读 AC 锚点、主会话单写勾选 `task.md`、多单元干净子上下文隔离、2～3 次盲修熔断 |
| 自审走过场与文档流水账 | 实施前四项规格对齐独立审查 + 交付前内部对抗验收闭环 | 首屏 30 秒可读、`task.md` ≤ 100 行当前态、同事项 Delta 差量续改 |

详细角色分工见 [Agent 职责与工作流](agent-responsibilities-and-workflows.md)，权威规则以 `workflow/`、`agents/`、`skills/` 为准；`docs/verification/` 与历史 `agent-features/` 作为旧版本归档保留只读。
