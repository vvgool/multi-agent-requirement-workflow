# 文档分工与差量规范

局部小修不建文档；持续事项在 `<features_dir>/<事项>/` 下以 `task.md` 为**唯一状态机、批准记录与复选框控制面**，由 [verify_feature.py](../skills/acceptance-testing/scripts/verify_feature.py) 在 `Spec Gate` 前与 `verified` 收口后做确定性校验。

## 按复杂度选择文档

| 复杂度 | 文档组合 | 职责边界 |
| --- | --- | --- |
| **明确局部小修** | 无新建文档 | 直接完成并简短返回改动与验证 |
| **常规持续事项** | 仅 `task.md` | 合并记录状态、批准、目标、可判定 `AC`、任务勾选与验证摘要 |
| **复杂跨模块事项** | `task.md` + `spec.md` + `verification.md` | `task.md` 唯一管状态、批准与勾选；`spec.md` 合一承载 `F/AC`（§1）与取舍、`Contract-First` 签名及单元切分（§2），**禁放可变状态头或复选框**；验收归 `verification.md` |

- **集合一致**：`spec.md` 与 `task.md` 的 `T1..Tn` 编号集合严格一致（兼容 `T1..T3` 范围写法，`pending_req_approval` 允许暂未拆 §2 单元），规则只写一次，不留自查填空栏。
- **唯一写入与勾选**：全事项仅 `task.md` 列表项允许 `- [ ] / - [x]`（禁表格复选框或重复 `T` 编号）；同批 `verification.md` 仅一人写入，复杂事项标 `verified` 前须落盘零复选框 `verification.md`（`通过 | 有条件通过`）。

## 人读文档格式

遵循**首屏 30 秒可读**，清除全部 `{{...}}` 占位符与空节：

1. **正交首屏**：
   - **`task.md`**：`> **阶段状态**`（`pending_approval | ready_to_implement | verified | pending_req_approval | blocked`）、`> **批准记录**` 与**当前结论**；待批时用 `## 本次请确认` 合并列必答项（`[Q编号 | 影响锚点] 决策点：推荐与理由；备选`，不设条数上限），获批后写入真实批准记录并删该节；Delta 重审追加 `Δ 待确认`，获批改写为 `Δ｜范围｜摘要｜日期`。
   - **`spec.md`**：标题 + **核心结论**，正文固定 `## 1. 目标、边界与验收标准` 与 `## 2. 架构取舍、接口契约与单元切分`。
   - **验证/缺陷报告**：`> **验收结论状态**` / `> **结论状态**`（`通过 | 有条件通过 | 未完成 | 阻塞`）。
2. **`task.md` 上限（≤ 100 行）与收口必检**：`Spec Gate` 前必过 `verify_feature.py --phase spec-gate`；**主会话回写 `verified` 后必过 `--phase verified`**（拦截超行、重复 `T`、残留 `待确认` / `## 本次请确认`、未勾项与非 `无` 阻塞）。
3. **状态枚举与精简证据**：验证表状态限 `通过`、`失败`、`未执行`、`阻塞`、`不适用（原因）`（`verified` 时至少 1 项 `通过` 且无未通过项）。**默认不建 `evidence/`**：优先用正式测试及命令+退出码摘要内联自证，禁落盘过程审查稿、常规输出或 `.txt` 临时测试（探针用完即清，禁仅留 `/tmp` 等易失路径；仅截图/基准等非内联产物按需入 `evidence/`）。

## Delta 差量续改与归档

同事项迭代沿用原目录，**禁建 `v2/v3` 目录**：就地更新 `spec.md` 与 `task.md` 当前态并用简短 **Delta（原行为 → 现行为 + 原因与受影响 AC/T）** 交代差异，历史细节交 Git 历史追溯。
