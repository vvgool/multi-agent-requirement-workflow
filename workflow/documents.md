# 文档分工与差量规范

文档服务于“30 秒看懂拍板”与“跨会话零歧义恢复”。局部小修不建文档；持续跟踪事项在 `<features_dir>/<事项名称>/` 下以 `task.md` 为**全事项唯一状态机、批准记录与复选框控制面**。

## 按复杂度选择文档

| 复杂度 | 文档组合 | 职责边界 |
| --- | --- | --- |
| **明确局部小修** | 无新建文档 | 会话内直接完成并简短返回改动与验证 |
| **常规持续事项** | 仅 `task.md` | 合并记录状态、批准记录、目标、可判定 `AC`、任务勾选与验证摘要 |
| **复杂跨模块事项** | `task.md` + `spec.md` + `verification.md` | `task.md` 唯一管状态、批准记录与勾选；`spec.md` 合一承载业务 `F/AC`（§1）与架构取舍、`Contract-First` 签名及单元切分（§2），**严禁在 `spec.md` 重复放置可变状态头或复选框**；验收证据归 `verification.md` |

- **单向追溯与零重复**：`spec.md（F/AC → D/Contract → T 切分）` 与 `task.md（状态/勾选）` 按稳定编号互链，规则只写一次，不建独立实施计划文件，模板不留自查填空栏。
- **验证报告唯一写入人**：同批次 `verification.md` 仅一人写入（默认主会话汇总，或派发卡片显式授权 `testing-agent` 单写）；复杂跨模块事项标 `verified` 前须落盘 `verification.md`，独立验收通过前首屏结论只能是 `未完成 | 阻塞`。
- **唯一任务勾选**：全事项仅 `task.md` 使用 `- [ ] / - [x]`；独立验收未通过前不得勾完所有任务。

## 人读文档格式

事项文档遵循**首屏 30 秒可读**结构，成稿删除模板填写提示与空节：

1. **控制面与规格正交**：
   - **`task.md` 首屏**：持有 `> 阶段状态`（`pending_approval | ready_to_implement | verified | pending_req_approval | blocked`）、`> 批准记录` 与**当前结论**；待批时用 `## 本次请确认` 一次性合并列出影响范围、`AC` 或核心取舍的必答项（`[Q编号 | 影响锚点] 决策点：推荐与理由；备选`，不设条数上限，常规可逆细节给推荐默认值不占此区）；获批后写入真实批准记录（范围｜原话摘要｜日期）并删去 `## 本次请确认`。Delta 重回待批时保留旧记录、追加 `Δ 待确认` 并临时恢复该节，获批后改写为 `Δ｜范围｜原话摘要｜日期`。
   - **`spec.md` 首屏**：仅写标题与**核心结论**，正文固定为 `## 1. 目标、边界与验收标准` 与 `## 2. 架构取舍、接口契约与单元切分`，零状态头、零复选框。
   - **验证/缺陷报告首屏**：持有 `> 结论状态`（`通过 | 有条件通过 | 未完成 | 阻塞`）。
2. **`task.md` 硬上限（当前态 ≤ 100 行）**：仅留当前目标摘要、活跃勾选、阻塞与最新验证链接，严禁堆历史流水账或借单行塞入长日志绕过上限。
3. **验证状态**：仅用 `通过`、`失败`、`未执行`、`阻塞`、`不适用（原因）`；长日志存仓库内 `evidence/` 后链接，严禁仅留 `/tmp` 等易失路径作唯一验收证据。

## Delta 差量续改与归档

同目标补充、返修与迭代统一沿用原事项目录，**禁止新建 `v2/v3` 版本目录**：

- **维护当前态 + Delta 差量**：直接就地更新 `spec.md` 与 `task.md` 当前有效规则，用简短 **Delta（原行为 → 现行为 + 原因与受影响 AC/T）** 交代差异，不堆失效旧方案。
- **证据归档**：调试过程与长输出沉入 `<事项目录>/evidence/` 或 Git 历史。
