# 文档分工与差量规范

文档服务于“30 秒看懂拍板”与“跨会话恢复”。局部低风险小修不建文档；持续跟踪事项在 `<features_dir>/<事项名称>/` 下维护唯一进度入口 `task.md`，已有项目文档可直接引用。

## 按复杂度选择文档

| 复杂度 | 文档组合 | 职责边界 |
| --- | --- | --- |
| **明确局部小修** | 无新建文档 | 会话内直接完成并简短返回改动与验证 |
| **一般持续事项** | 仅 `task.md` | 合并记录目标、AC、简要方案、任务勾选与验证摘要 |
| **复杂跨模块需求** | `task.md` + `requirements.md` + `technical-design.md`（及 `verification.md`） | `task.md` 管状态与一行一单元的任务勾选；规则/AC 归需求，架构/契约/文件变更与单元切分归设计，输出证据归验证；不另建实施计划文件 |

- **单向追溯与零复述**：`需求（F/AC）→ 设计（D）→ 任务（T）→ 验证` 按稳定编号引用；规则只在需求写一次，设计不复述业务规则，模板不留“起草者自查”填空栏。
- **验证报告唯一写入人**：同一批次 `verification.md` 仅一人写入（默认主会话汇总，或验收派发卡片显式授权 `testing-agent` 单写）；分单元开发仅在返回卡片上报 RED→GREEN，独立验收通过前首屏结论只能是 `未完成 | 阻塞`。
- **唯一任务勾选**：仅 `task.md` 使用 `- [ ] / - [x]`；计划与阶段稿不维护第二套复选框。必需独立验收未通过前不得勾完所有任务。

## 人读文档格式

所有事项文档遵循**首屏 30 秒可读**结构，成稿删除填写提示与空节：

1. **首屏三要素**：
   - `> 阶段状态`：`pending_req_approval | req_approved | pending_design_approval | ready_to_implement | verified | blocked`（验证/诊断报告标 `通过 | 有条件通过 | 未完成 | 阻塞`）；
   - **核心结论**：1～2 句话点明根本问题、方案与边界；
   - **`> 批准记录` 与 `## 本次请确认`**：待批时写 `批准记录：待确认`，并用 `## 本次请确认` 列出查清代码后仍影响范围、行为、`AC` 或关键取舍的必答项（每项 `[Q编号 | 影响锚点] 决策点：推荐方案与理由；备选`，不设条数上限，多项按主题分组、一次性合并提出，常规可逆细节给推荐默认值不占此区，严禁为压缩条数隐瞒未决项或拆轮追问）；获批后改写首屏一行真实批准记录（范围｜原话摘要｜日期）并删除空的 `## 本次请确认` 节。Delta 续改重回待批时保留旧记录并在其后追加 `Δ 待确认`，临时恢复该节仅列新增拍板项；获批后把 `Δ 待确认` 改写为 `Δ｜范围｜原话摘要｜日期` 并再次删节，旧记录不得覆盖。
2. **`task.md` 硬上限（当前态 ≤ 100 行）**：仅保留当前目标摘要、活跃勾选、阻塞与最新验证链接，严禁堆成历史流水账。
3. **验证状态**：仅用 `通过`、`失败`、`未执行`、`阻塞`、`不适用（原因）`，不预填通过；长日志存 `evidence/` 后链接。

## Delta 差量续改与归档

同目标补充、调整、返修与迭代统一沿用原事项目录，**禁止新建 `v2/v3` 版本目录**：

- **维护当前态 + Delta 差量**：直接更新 `requirements.md` 或 `technical-design.md` 当前有效规则，并在变更节用几行 **Delta 差量（原行为 → 现行为 + 原因与受影响 AC/任务）** 交代差异，不堆叠失效旧方案。
- **证据归档**：调试过程与长输出沉入 `<事项目录>/evidence/` 或 Git 历史，主文档仅留结论与链接。

## 图示与代码块

优先用图表替代冗长文字，图后仅补关键边界与异常：

| 内容 | 形式 |
| --- | --- |
| 业务流程与异常分支 | Mermaid `flowchart` |
| 模块职责、数据归属与依赖 | Mermaid `flowchart`（`subgraph`） |
| 跨模块调用与异步时序 | Mermaid `sequenceDiagram` |
| 状态流转与触发条件 | Mermaid `stateDiagram-v2` |
| 接口、配置与验证命令 | 带语言标识代码块 |
| 方案取舍、AC 与检查结果 | 紧凑短表 |
