# 共享与路径定位

启动框架、共享给其他用户或搬迁工作空间时读取本文。可分发文件中的路径以框架或工作空间为基准，不依赖作者的用户名、主目录或安装位置。

新项目初始化、版本锁和本地缓存先按 [框架包规则](package.md) 执行。框架内容不默认进入业务仓库；以下动态路径及历史保护原则同样适用于三个宿主。

## 定位两个根目录

- 框架根目录：新锁定安装从项目workflow.lock.yaml取得包摘要并核对 `.agents/requirement-workflow-cache/<sha256>`；缓存缺失先补同版本。无锁的旧快照或手动原型从宿主实际加载的 agents/coordinator-agent.md 所在目录向上一级确定。文件来源位置不可取得时，使用用户已提供的框架目录；仍不明确才询问，不能从历史任务或使用示例中推断。
- 工作空间根目录：使用用户指定的目标工作空间，或用户明确采用的当前宿主项目根目录。Shell cwd 不一定是宿主项目，不能自动等同。
- 规则和模板路径相对框架根目录；features_dir 相对工作空间根目录；产物路径相对需求目录；文档来源按其 source_revision 和 path 定位。

共享说明及模板不填入任何人的实际根目录。宿主文件工具或子 Agent 派发需要绝对路径时，协调 Agent 根据当前两个根目录动态解析、校验，然后填入当次运行上下文。运行时绝对路径是当前机器的定位信息，不是安装约定。

## 迁移或换机器后恢复

1. 在新宿主确认当前框架和工作空间位置，读取本机 workflow.yaml 和需求状态。以现存目录、feature_id 和当前配置定位，不沿用旧 status/task 中的 workspace_root、framework_root 等路径访问旧目录。
2. 核对旧 active_run。存在未确认结束的任务时先报告阻塞；搬目录或换机器不证明旧任务已结束，不能直接清空后重派。
3. 旧任务确认结束后，重新解析当前目标项目、需求与产物。目标项目在工作空间外且无法唯一定位时询问用户，不猜测新路径。核对内部 ID、修订、文件内容与审批摘要；路径变化本身不等于正文获准变更。
4. 更新当前根状态中的本机定位信息并记录 relocation 事件，按状态规则递增版本。历史 run、来源快照、审批 manifest 保持原样；旧绝对路径只作来源证据，不是当前可访问路径的保证。
5. 协议2续原task并追加本机调用，协调在无活动调用时核实并更新本机定位字段（身份不变），旧host输入/授权与结束事实保持原样；协议1沿原包新run规则。单纯等待审批时核对原内容及来源再展示，不因搬迁而重复派发产品。

若证据中的本地来源已无法定位或读取，阻塞并请用户指定来源；不能把旧快照冒充最新正文。旧宿主的任务标识也不保证能在新宿主重连。

## 分享内容

独立框架包：framework.yaml、LICENSE（存在时）、AGENTS.md、README.md、agents/、skills/、workflow/、templates/ 和无凭据的 workflow.yaml 示例，清单摘要算法见包规则。业务项目仅提交workflow.yaml、workflow.lock.yaml、简短入口和各目标宿主薄角色/忽略区块。接收者在自己的工作空间维护配置和 agent-features。

本框架开发需求 agent-features/、早期 docs/superpowers/、docs/verification/ 下的完整演示证据和运行记录仅保留维护者本地并被根 .gitignore 排除，可能含机器路径及项目内容，不随当前源码或核心包分发。仓库保留当前规划及精简验证摘要；业务项目按 [共享成果规则](output-layout.md#共享成果与本机现场) 保留正式文稿与可共享入口，忽略 `.workflow/` 本机执行现场。确需共享需求历史时由用户明确选择，按迁移步骤恢复，而不是将其视为新用户的默认工作空间。

角色文件仍需宿主真实注册。使用通用 [初始化Skill](../skills/setup-requirement-workflow/SKILL.md) 为当前Codex、Claude Code或OpenCode生成相应薄入口；另一个人/机器按同一锁补本地缓存并验证当前宿主，不直接沿用其他人的激活回执。旧Codex快照按兼容流程保持，不自动升级。文件安装、真实新会话生效和完整需求闭环分别验证。
