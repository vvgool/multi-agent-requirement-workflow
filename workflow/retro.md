# 轻量复盘

复盘是完成、阻塞或重大返工后的可选动作，用于改进下一次判断。它不增加审批阶段，不改变已确认的需求，也不创建第二个 `task.md` 或机器任务账本。

## 触发与范围

以下情况适合复盘：复杂需求完成、最终验收发现返工、同类 Bug 重复出现、宿主恢复/交接出现偏差，或用户指出流程质量问题。一次性明确小修通常无需复盘。

复盘只覆盖本事项和可复用的流程事实，不评价个人；业务问题仍写在需求/设计/验证文档，宿主问题按 [会话级诊断](session-diagnosis.md) 处理。

## 最小记录

在原 `verification.md` 或 `task.md` 末尾追加短表，避免另建报告：

| 项目 | 内容 |
| --- | --- |
| 预期 | 当时依据的用户目标、规则和完成门槛 |
| 实际 | 真实改动、失败、恢复和验收证据 |
| 偏差 | 哪个假设、边界或证据不足导致偏差 |
| 动作 | 下一次要新增、删除或调整的规则/模板/验证 |
| 责任与条件 | 原文档写入者、完成时间或触发条件 |
| 验证 | 如何证明动作生效；未执行则保持待办 |

动作必须可执行且与证据相关，例如“复杂需求实施前补状态/并发检查”，不要写成“加强沟通”。同一事项后续修复更新原段落，保留原失败事实和复验结果。

## 收口规则

协调者只将已实施且验证通过的动作标记完成；建议和未验证假设保持开放。复盘不能把局部案例推广为所有宿主、生产或 Superpowers 的性能结论，也不能替代最终独立验收。
