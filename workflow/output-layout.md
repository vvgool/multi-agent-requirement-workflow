## 固化正式成果

1. 按 [交接核对](routing.md#交接核对) 确认任务结束且交接有效后，选择实际文稿；同次未变的核对结果直接使用。按结果的 kind 选择：产品 ready 固化 requirements（quality_check 指向同文稿时不复制第二份）；开发 ready 固化 development_record，或 technical_plan、implementation_plan、verification；测试的 passed/failed/blocked 报告在交接有效时均可固化，状态和未执行项须如实展示。其他问题或阻塞仅在需求入口说明，不冒充正式交付。
2. 仅将符合上文共享成果要求的文稿按上述固定文件名固化到 documents/；脚本、日志、基线和 sources 留在原任务。使用副本，不用硬链接/符号链接把已批准内容绑定到可变候选。文稿中本地引用写为 Markdown 相对链接；固化时先将来源目标和正式文稿父目录都解析为真实路径，再以同一基准计算相对链接（包括 /var 与 /private/var 等宿主路径别名），指向同批固化或已有的共享成果、项目文件及外部来源；执行证据留在 result/artifacts，不放正文链接。从正式文件位置核验每个链接，并在不读取 .workflow 的条件下核对正文及引用仍可用；无法满足时退回角色补齐文稿，不删改已批准内容。重定位后的正文才是评审和审批对象，不能沿用候选文稿的摘要。未经索引的附加文稿不自动发布。
3. 写入前核对目标与来源真实路径不冲突。目标已存在时，只有根 artifacts 明确记录为本版受管理的正式文稿且当前摘要匹配，才可更新；同摘要可保留。用户修改、来源不明内容或符号链接冲突时停止。布局4已评审正文（含待审稿）及manifest先按[基线固化与恢复](incremental-changes.md#评审固化与恢复顺序)保存不可变reviews；同目标进行中范围变化可在保全历史后更新documents当前稿，不复制整套修订目录。旧布局沿原规则不替换。旧交付 候选和有效失败证据保留，正式位置只代表本版当前有效报告。
4. 内容变化时采用同目录临时文件准备后原子替换，同内容且归属已核实的目标直接保留。根 artifacts 只记录正式 path、kind、revision、baseline_id、task_id、delivery_id、sha256；候选来源路径和摘要从对应任务的 result.deliveries中对应交付的artifacts 按 kind 唯一解析，不重复保存 source_path/source_sha256。固化前核对该交付 的身份、来源普通文件/授权路径及真实摘要，缺项或同 kind 多个来源时阻塞，不猜选。旧索引保留并核对原来源字段。确认文件及引用有效后再推进状态，最后按实际状态更新 README。固化中断时先比较候选、目标、已存索引与状态，只有能证实同一有效交付 的同内容写入才补完；不一致则阻塞，不猜测成功。
5. 修复轮次进入原任务的新调用/交付 时，入口将旧报告标记为“上一基线，当前待重验”；新报告完成交接后才更新正式文件及其来源索引。不得让上一轮 passed 看起来已覆盖新代码。切新版时入口指向新版，旧版文档和审批保留。

## 人工入口

协调层使用 [需求入口模板](../templates/feature-readme.md) 创建需求根 README.md。只列当前版本、阶段、真实进度、待确认事项、已存在的共享正式文档；来源task及delivery在根artifacts仅登记任务目录入口，结果与证据索引留run内，不在 README 链接内部任务或证据；启用 Issue 时按 [Issue 规则](issue-tracking.md) 分别展示本地技术独立验收、最终完成确认、关闭许可、发布适用性及实际事实、真实绑定及远端open/closed、最新已核实进度链接和未完成/未知同步提示（包括旧目标unknown数量），从未启用且无历史记录时省略；不重复文档正文、日志或完整验收表。未产出、过期、失败、阻塞要明确标注。默认人工确认当前 requirements.md，交付时看 test-report.md 与实际功能；技术决策需要人时链接适用开发文档，不新增所有阶段的强制审批。

README在首次创建、修订/阶段变化、出现或解除阻塞/待决策事项、正式成果或其有效性变化（含新修复轮使旧报告待重验），以及Issue绑定/同步提示实质变化时更新。同一动作合并一次更新；unknown/running切换保存在 host.yaml、状态版本和 active_run，不重复写事件，普通方案通知在对话转达，常规任务进度只更新当前实现计划（简版为 development.md）；无变化的轮询不写入。恢复时只补符合这些条件的遗漏更新；存量方案通知仍按其原兼容协议。

README 是派生索引，不代替状态或审批；恢复时核对 status.yaml 并修正索引。生成后在根 artifacts 记录 kind: feature_index、path: README.md 和 sha256；下次只更新可由索引及摘要确认属于框架的入口。已有用户 README 或入口被用户编辑时不覆盖，先报告冲突。旧布局可在无路径冲突时生成指向已有文稿的入口，不搬旧文档。对话同步给出该需求目录、版本和待办。

## 保留与清理

- 保留：输入、正式文稿、审批、状态/事件、任务/结果、有效配置、必要 Issue 绑定与同步记录，以及复现结论/缺陷所必需的来源、脚本和执行证据。同一检查保留一份必要输出并引用，短记录可直接放 result.summary，不强制独立执行日志、证据文件或脚本；不为父层或多个报告重复抄存。无外部来源时 review manifest 的 sources 为 []，不新建空 sources/；旧来源清单继续校验。
- 仅清理：协调确认宿主调用确已结束后，逐项核对本轮 tmp/ 或 task 明确授权的临时位置。真实路径必须在授权范围内、归属及创建后已知内容可核实，且所有现有文稿/产物/审批/证据无引用，无 pending/暂存恢复依赖、无用户修改。任一条件无法证明则保留并在现有记录说明原因；执行角色仍活动时保留现场。只允许清理满足全部条件的临时内容，不能用目录整体删除连带移除受保护文件或沿符号链接操作。
- 收敛后核对持久文稿及必要证据链接仍可读，在已有结果交接/状态事件记录清理对象与判断即可，不新增每文件清理报告。outputs/、sources/、历史 run 和必要失败证据继续保留；不按天数、体积或 completed 批量清理，不把 pending 和候选提交暂存误当普通缓存。
- 框架开发验证：完整安装副本、一次性检查和重复源快照默认在宿主临时目录；仓库仅留精简结论及必要可复现证据，正常闭环示例保留一套。不复制整个隔离项目作为每轮修复的新归档；历史证据保持原索引，不追溯清空。共享核心不包含这些测试现场。

## 开发中候选展示

按 [方案通知](execution-contract.md#开发中方案通知) 读取当前任务文稿，在对话标明文稿版本及“开发中方案，未验收”；README仅在 [人工入口](#人工入口) 的更新时机合并简短方案状态及缺口，不链接本机候选或通知。普通展示不创建显示状态、事件或产物索引，不清活动任务、不推进阶段。实质阻塞、需决策或最终交接时按原状态规则更新。

协调不代写候选；用户修改README或正式文稿时保留并说明冲突。最终以真实result的文稿摘要和代码基线为准，核对后按固化规则发布成果。旧run的进度清单及展示记录仅按 [存量协议](legacy-plan-notifications.md) 读取，不迁移或补造。

## Bug 成果

独立 Bug 的正式边界稿为 documents/bug-boundary.md，修复记录为 documents/bug-report.md；协调依据已核对的 run 输出固化，历史修订不改。边界评审沿文档审批算法；测试报告沿既有位置。内部假设/迭代原始证据放各自任务 输出，文稿独立说明原因与结果，不链接本机现场。
