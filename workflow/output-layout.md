# 事项入口与成果

一次性局部低风险小修直接完成，无需建文件。需要持久跟踪时，以 `<features_dir>/<事项名称>/task.md` 作为唯一协调入口，使用 [任务模板](../templates/task.md)。一个事项可以包含多个实施任务和多份职责明确的文档；按 [文档分工](documents.md#按复杂度选择文档) 选择，task.md 保持当前状态、任务勾选、依赖、阻塞、验证摘要及相关链接。

复杂需求采用以下结构，已有项目文档按职责直接引用；文件按实际需要创建，不预建空稿：

```text
<事项名称>/
├── task.md                  # 协调、进度、未决项和链接
├── requirements.md          # 业务需求和验收标准
├── technical-design.md      # 技术设计和关键决策
├── implementation-plan.md   # 实施单元、依赖、文件归属和检查方法
└── verification.md          # 实际验证及证据，进入验收时维护
```

同一内容由一处维护：task.md 引用业务规则、技术细节和检查证据，不全文复制。每个共享文件保持单写，宿主原生任务保存派发与结束事实。代码、交付文件和失败日志按项目约定保存，只引用必要证据；共享内容不得泄露凭据。不额外建立README索引、机器业务账本、逐轮快照或版本目录。

历史目录和旧模板仅由原锁定版本读取，不批量搬迁、清理或重算。
