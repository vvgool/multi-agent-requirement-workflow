# 执行约定

协议3优先在当前会话执行，需要持久跟踪时才维护一个当前协调入口；不要求task.yaml、invocation_id、授权版本、delivery或根状态。旧任务仍使用其原锁定包，不用本包补写旧记录。

## 接单与执行

独立一次性、明确局部低风险且非旧任务续接的小修，直接按已载项目入口的授权/风险/未知操作边界处理，不先读锁、缓存、协调规则或完整框架包；实际使用框架协作/角色/恢复/安装时才核验。旧任务始终原锁原包。

先确认目标项目、目标和允许修改的范围，遵循适用项目规则。一次性、局部低风险且目标明确的小修，由当前会话直接定位→最小修复→相关回归→简短返回；无需先建文档、清单、计划或宿主原生任务，也不默认另派角色。只有跨会话恢复、交接或多步持久跟踪确有需要时，才维护当前协调入口，可参考 [任务模板](../templates/task.md)。普通对话和一次性问答不为留痕建文件。只读请求不修改。信息不足提出具体问题，不为了走流程重问已有授权。

协调Agent按 [路由判断](routing.md#路径选择) 主动选择路径和专业责任，不等用户提醒拆分或审查。一个事项只能有一个主流程控制者：项目锁定的 requirement workflow 已生效时，其他端到端 workflow 只能提供局部方法，不得新增自己的阶段、审批、账本、目录或提交门槛；用户扩大范围时更新当前事项，不重启第二套流程。原因未知先由同一角色沿真实调用链定位，不自动转完整阶段链，不按行数或耗时分类。复杂需求按 [文档分工](documents.md#按复杂度选择文档) 在实施前形成或引用独立需求和技术设计，按依赖拆分实施任务，验收时记录实际证据；task.md 只管协调和进度。一般事项可合并记录，小修仍直接执行。一个事项可包含多个实施任务，不因文档拆分或角色变化复制需求、另开事项。

创建或更新人读文档时读取 [格式规范](documents.md#人读文档格式)，按实际内容选择对应模板与图示；没有产稿需要的小修不触发这次读取。

## 实施与完成门槛

以下是相应工作的完成条件，不增加统一人工阶段审批。明确局部小修直接完成；一般需求补齐局部决策和必要方案。复杂需求由协调Agent主动核对：

| 检查点 | 可以推进的条件 |
| --- | --- |
| 需求就绪 | PRD核心旅程、功能/规则、验收和决策边界清楚，建议与未验证假设可区分 |
| 设计就绪 | 模块职责、数据拥有者、输入输出、状态及依赖明确；核心旅程能闭环；可以有依据地复用现有模块 |
| 实施就绪 | 功能/验收有实施任务承接，准确范围、前置条件、消费/产出契约、检查方法及集成负责人明确；必需实施前独立审查完成，阻断问题已解决 |
| 批次完成 | 实际行为满足该批次交付条件，相关验证和必需审查已执行，缺陷与遗留有明确归属 |
| 整体完成 | 跨模块集成及关键用户旅程通过，最终独立验收完成，无影响交付的未决 |

复杂需求至少安排实施前独立审查和最终独立验收。审查需求、设计和计划的内容与一致性，不以文件/标题齐全判定；专业分工见路由。实施中按可核对交付批次安排审查，公共契约、状态和高风险变更重点检查，不按文件数机械派发。稳定部分可先审查，后续变化检查受影响范围。

起草者完成自检后，由未参与起草的适任角色独立审查；实现者自验不能代替最终独立验收。协调者安排必要角色，缺能力时如实说明阻塞；自检只可作为背景。审查未运行测试就明确未运行，代码阅读不等于执行通过。必需角色/环境缺失时不将相应任务勾完，可继续已授权且独立的部分。

Bug引起架构/契约调整时复用已有需求，仅补受影响设计、计划及必要独立检查；一般Bug不套完整PRD链。已有确定的需求与设计可引用，但核对适用性。关键未决解决前不实施依赖它的部分。

可自动验证的业务行为默认按 [测试先行](test-first.md) 执行；既有失败测试可复用。文稿、视觉等不为形式新增测试。例外说明原因与替代验证，保留实际证据；不将事后测试称为TDD。纯重构先建立有效行为保护。项目既有明确规则和用户要求优先。

## 共享与交接

每个共享文件只设一个写入者。委派明确文档路径、目标、允许改动的文件/范围及所需结果；主会话与执行者避免并写文档。执行者可返回实际结论，由原文档写入者合并；原生任务已有的派发、运行和结束事实不再写机器副本。

交接与恢复先读协调入口，再按职责读取相关需求、设计、计划、验证段落、代码及原生任务。保留已验、失败、未决和必要任务引用。需要确保独立验证针对相同内容时，只核对相关文件版本/摘要；完整的文件清单保留在本地，模型只读取核对结论和差异。断连、服务重启或旧streaming记录按[恢复判定与接续](host-adapters.md#恢复判定与接续)查询原执行、核对结果并接续未完成部分；更换会话/宿主同样先查原调用，未知不等于结束，不重复派发或重放外部操作。

## 何时确认与独立验证

范围或验收存在分歧先确认具体问题；付款、权限、数据删除或大范围共享逻辑变更先确认范围，另由一名角色独立验证。新范围不继承无关旧授权。已确认范围内继续推进；创建文档、切换角色或实施单元不触发重复批准或执行方式选择。项目规则统筹流程，通用 Skill 只补充适用方法。简单已知修改无需统一阶段审批或边界报告。

验证按实际影响选择相关现有检查，不默认全量测试，不为凑证据新增无意义测试；未执行不报通过。完成声明必须引用与当前文件/提交和授权范围匹配的最近一次实际证据，说明命令或操作、实际结果和未检查范围；局部通过不能外推整体完成，代理自述不能替代回读。失败结论保留；修复后更新当前待办和真实重验结论，不创建版本目录或第二套报告。原因不清的缺陷按 [系统化诊断](../skills/bug-fixing/references/systematic-debugging.md) 保留症状、真实链路、可证伪假设、区分检查和根因依据；完成前按 [完成前证据门槛](../skills/acceptance-testing/references/completion-gate.md) 分别核对范围、行为、TDD、独立验收、环境和外部状态。每次失败后先分类并写出能区分根因的新证据；没有改变假设、失败类别或验证范围时停止修改，转会话诊断或交接。外部写入结果未知时先查询原调用，不重放。

## 完成

对话简短返回改动、实际验证和限制；已有文档或确需持久跟踪时再合并结果，不为了完成记录新建文件或原生任务。仅当必需验证完成、无影响交付的未决项时说明完成。自验与独立验收分别表述，不宣称实际token或时间收益。
