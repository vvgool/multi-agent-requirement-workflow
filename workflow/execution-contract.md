# 执行约定与门禁

核心原则：第一性原理直击本质、小修零仪式直通、不确定性驱动单次 `Spec Gate` 对齐、实施期静音连续巡航不偏航。全事项唯一状态与进度入口为 `<features_dir>/<事项名称>/task.md`。

## 人工确认

明确既有契约内的局部低风险小修 `0` 门禁直接完成。新功能、行为调整及架构性变更按 `task.md` 唯一持有的 **5 阶段状态枚举**推进：

```text
主路径：pending_approval → ready_to_implement → verified
按需扩展态：pending_req_approval（仅超大模糊范围先锁 F/AC 防白做架构时选用）｜ blocked（命中真阻塞白名单）
```

1. **第一性原理穿透 XY 表象、先查代码合并澄清**：动笔或提问前先读相关代码、配置与测试，剥离口述“表面解法”追问“根本矛盾与硬约束”；常规可逆细节给推荐方案，**真正影响范围或验收的未决业务分叉一次性合并提出**（超大模糊项目可选先停 `pending_req_approval` 锁业务边界再做架构）。
2. **后台前置审查与单次 `Spec Gate`（`pending_approval → ready_to_implement`）**：
   - 意图明确时（含跨模块/状态性复杂事项），Agent 先在后台完成规格设计（先删减简化、再将机械约束下沉至代码/类型/脚本）及适用的独立四项规格对齐审查闭环，消除内部阻断后向用户发起 **1 次 `Spec Gate`（`pending_approval`）** 并结束本轮；未获明确批准前严禁修改正式业务源码。
   - **受控 `Spike` 探索通道**：UI 体感或高不确定技术探索确需先看可运行原型才能定 `AC` 时，允许在显式隔离路径/写集且不触碰支付、权限、删数据或非幂等外部写的前提下先交付最小原型，收敛后再经 `Spec Gate` 补齐正式契约与验证；严禁把探针/夹具拆成多轮微型审批循环，严禁将纯原型/探针通过标为 `verified`。
3. **真实批准判定**：推荐优先调用宿主原生交互问答组件；确认选项必须具备明确授权语义，严禁仅凭业务参数澄清选项流转状态。业务澄清或异步工具回执（如 `accepted:true`）绝不等于批准，须等待真实用户授权；AI 审查不替代人审，批准不追溯覆盖越界写入。
4. **局部重确认与高危护栏**：实质变更 `AC` 或核心契约时仅重确认受影响部分。涉及**付款、权限、数据删除或大范围共享逻辑变更**须先确认具体范围并另由独立角色验证；**结果未知的外部操作**先查原调用，幂等性未确认前保持 `blocked`，严禁自动重放或补偿。

## 静音连续巡航与抗偏航

进入 `ready_to_implement` 后开启**静音连续巡航**（`T1..Tn → 联调自验 → 内部独立对抗验收 → 缺陷返修闭环`）：

### 中途打断白名单（唯一允许暂停询问的 3 类真阻塞）
除以下 3 类外，**严禁因汇报进度、切换单元或常规报错修复而中途询问“是否继续”**：
1. **契约证伪**：实测新证据证明已批规格或核心契约不可行，必须修改外部行为或关键架构；
2. **高危副作用**：触及未明确授权的支付、权限、删数据、生产发布或结果未知的非幂等外部写入；
3. **外部凭据缺失**：缺少仅用户可提供的密钥或远端环境（须先跑完其余独立单元后集中反馈）。按锁文件安装本地依赖、复用当前宿主运行隔离验证、隔离环境内生成随机合成密钥/假数据均非打断白名单，声称缺环境前须先核实本机隔离可行性。

### 长跑抗偏航四道硬锁
1. **单元锚点只读回读 + 主会话单写勾选**：每完成一个单元须**只读回读** `task.md` 首屏目标及对应 `AC` 原文确认无缩水无越界；由主会话单写更新 `task.md` 勾选。
2. **多单元干净子上下文隔离**：多单元任务按正交写集派发干净子上下文执行，隔离长对话噪声。
3. **2～3 次盲修熔断**：每次失败先写出区分根因的新证据；**同一故障连续 2～3 次修复失败且未缩小根因范围时立即熔断停手**，转系统化根因诊断重核调用链与契约。
4. **交付前内部验收自闭环**：实施完成后自动拉起全新独立 `testing` 会话按 `AC` 与最高风险反例运行验收；非白名单缺陷内部返修复验直至 `verified` 后一次性交付。

## 实施与完成门槛

| 检查点 | 准入/完成条件 |
| --- | --- |
| **规格就绪（Spec Gate）** | 根本矛盾、硬约束、可判定 `AC`、删减取舍、数据唯一写入者、接口签名与 `T1..Tn` 明确；适用独立四项审查无阻断；用户已批准（`ready_to_implement`） |
| **单元完成** | 契约与行为检查通过，已只读回读 `AC` 锚点确认无缩水无越界 |
| **整体完成** | 正式实现主链路与最高风险反例经全新独立角色真实运行验证通过，无未决阻断（`verified`） |

## 契约先行与分层验证

- **业务与脚本代码（`Contract-First` + 行为级 TDD）**：多模块/多单元先落共享接口签名、类型与异常契约及失败测试（核实真实 `RED`），再做最小行为实现至 `GREEN`；不适用时如实说明替代验证。
- **文档、规则与配置演进（`SDD` + 纯结构/拓扑门禁 + 对抗审查）**：以 `SDD` 明确边界与不变量，机械门禁仅校验确定性结构（Schema、真实文件与 GFM `#标题锚点` 可达性、格式红线、体积上限），严禁编写跨文件自然语言措辞快照断言。
- **基础事实推导（拒绝经验类比盲试）**：排障或熔断时回到真实数据流、状态唯一写入者与物理边界推导首个破坏不变量的根因；未实际运行严禁报通过。
