# 执行约定与门禁

核心原则：第一性原理直击本质、小修零仪式直通、复杂变更两次精准对齐、实施期静音连续巡航不偏航。唯一进度入口为 `<features_dir>/<事项名称>/task.md`。

## 人工确认

明确既有契约内的局部低风险小修直接完成。新功能、行为调整及架构性修复按显式**阶段状态枚举**推进：

```text
pending_req_approval → req_approved → pending_design_approval → ready_to_implement → verified（真阻塞记为 blocked）
```

1. **第一性原理穿透 XY 表象、先查代码合并提问**：提问前先读相关代码、配置与测试，剥离口述“表面解法”追问“根本矛盾与不可妥协硬约束”；常规细节给推荐方案，**真正影响范围或验收的必答业务决策一次性合并提出**。
2. **两道 `<HARD-GATE>` 停点**：
   - **`STOP 1`（`pending_req_approval`）**：展示需求与 AC 并请求批准后结束本轮。**业务澄清不等于需求批准**——仅回答业务参数时须合入需求重新请求批准，不提前进入正式设计。
   - **`STOP 2`（`pending_design_approval`）**：需求确认后进入正式设计（遵循**先删减简化、再机械下沉**，砍掉冗余假设与中间层，把机械约束交给代码/类型/脚本）；复杂或状态性设计须在设计确认前核对审查适用性并完成独立四项对齐审查，消除阻断后展示设计请求批准并结束本轮。设计确认后实施，未获批准前严禁编写业务实现代码。可行性探针须在 `STOP 2` 前最小取证或并入已批 `T1`，严禁将探针/测试夹具拆成多轮 `pending_design_approval` 循环，未完成对应业务源码实现前严禁将纯探针/夹具通过标为 `verified`。
3. **真实批准判定**：等待真实用户回复后再判断批准。**提问受理不等于用户答案**（异步工具返回 `accepted:true` 或默认选项均不算批准）；AI 审查不替代人审，批准不追溯覆盖越界写入。
4. **局部重确认与高危护栏**：实质改变预期、AC 或架构取舍时仅重确认受影响部分。涉及**付款、权限、数据删除或大范围共享逻辑变更**须先确认具体范围并另由一名角色独立验证；**结果未知的外部操作**先查原调用，幂等性未确认前保持阻塞，严禁自动重放或补偿。

## 静音连续巡航与抗偏航

进入 `ready_to_implement` 后开启**静音连续巡航**（`T1..Tn → 联调自验 → 内部独立对抗验收 → 缺陷返修闭环`）：

### 中途打断白名单（唯一允许暂停询问的 3 类真阻塞）
除以下 3 类外，**严禁因汇报进度、切换单元或常规报错修复而中途询问“是否继续”**：
1. **契约证伪**：实测新证据证明已批需求或核心设计契约不可行，必须修改外部行为或关键架构；
2. **高危副作用**：触及未明确授权的支付、权限、删数据、生产发布或结果未知的非幂等外部写入；
3. **外部凭据缺失**：缺少仅用户可提供的密钥或环境（须先跑完其余独立单元后集中反馈）。按锁文件安装本地依赖、复用当前宿主运行隔离验证、隔离环境内生成随机合成密钥/假数据均非打断白名单，声称缺环境前须先核实本机隔离可行性。

### 长跑抗偏航四道硬锁
1. **单元锚点只读回读 + 主会话单写勾选**：每完成一个单元须**只读回读** `task.md` 首屏目标及对应 `AC` 原文确认无缩水无越界；由主会话单写更新 `task.md` 勾选。
2. **多单元干净子上下文隔离**：多单元或重耦合任务按单元（写集正交可并行）派发全新干净子上下文执行，隔离历史日志污染。
3. **2～3 次盲修熔断**：每次失败先分类并写出区分根因的新证据；**同一故障连续 2～3 次修复失败且未缩小根因范围时立即熔断停手**，转系统化根因诊断重核调用链与设计契约。
4. **交付前内部验收自闭环**：实施完成后自动拉起独立 `testing` 角色按 `AC` 与最高风险反例运行验收；非白名单缺陷内部返修复验直至 `verified` 后一次性交付。

## 实施与完成门槛

| 检查点 | 准入/完成条件 |
| --- | --- |
| **需求就绪** | 根本矛盾、硬约束、可判定 AC 与非目标清楚；事实与假设区分；用户已确认（`req_approved`） |
| **设计就绪** | 冗余假设已删减、模块边界、数据唯一写入者、接口与异常契约明确；适用四项审查无阻断；用户已确认（`ready_to_implement`） |
| **单元完成** | 行为检查通过，已只读回读 `AC` 锚点确认无缩水无越界 |
| **整体完成** | 业务实现主链路与最高风险反例经独立角色真实运行验证通过，无未决阻断（`verified`） |

## 测试先行与根因诊断

- **测试先行（TDD）**：可自动验证的行为与修复默认先写失败测试（确认真实 RED 原因）再最小实现至 GREEN 并做必要重构；不适用场景说明原因与替代验证，事后补测不伪称 TDD。
- **基础事实推导（拒绝经验类比盲试）**：排障或熔断时严禁凭经验类比套补丁，必须回到真实数据流、状态唯一写入者与系统物理边界推导首个破坏不变量的根因。
- **精准验证**：按影响选择相关检查，不凑数写无意义测试；未运行严禁报通过。
