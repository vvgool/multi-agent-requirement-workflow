# 执行约定与门禁

核心原则：第一性原理直击本质、小修零仪式直通、不确定性驱动单次 `Spec Gate` 对齐、静音连续巡航与 `verify_feature.py` 确定性收口。全事项唯一状态与进度入口为 `<features_dir>/<事项>/task.md`。

## 人工确认

既有契约内明确局部低风险小修 `0` 门禁直通。非小修按 `task.md` 唯一持有的 **5 阶段状态枚举**推进：

```text
主路径：pending_approval → ready_to_implement → verified
按需扩展态：pending_req_approval（超大模糊范围先锁 F/AC）｜ blocked（命中真阻塞白名单）
```

1. **穿透 XY 表象与合并澄清**：动笔前先读代码、配置与测试，追问根本矛盾与硬约束；可逆细节给推荐值，**影响范围或验收的必答分叉一次性合并提出**。
2. **后台前置审查、`--phase spec-gate` 与单次 `Spec Gate`**：
   - 意图明确时后台完成规格设计（先删减简化、再将机械约束下沉至代码/脚本）、异体四项对齐审查，并跑通 [verify_feature.py](../skills/acceptance-testing/scripts/verify_feature.py) `--feature-dir <目录> --phase spec-gate` 后，发起 **1 次 `Spec Gate`（`pending_approval → ready_to_implement`）** 结束本轮；未获批严禁改正式源码。
   - **受控 `Spike`**：UI 体感或高不确定技术探索确需先看原型定 `AC` 时，限显式隔离路径且禁触支付、权限、删数据或非幂等外部写，收敛后转 `Spec Gate` 补正式契约；禁拆多轮微审批，禁标纯原型为 `verified`。
3. **真实批准判定**：优先调用宿主原生问答组件（确认项具明确授权语义）；仅答澄清参数或异步受理回执（`accepted:true`）绝不算批准；AI 审查不代人审，批准不覆盖越界写入。
4. **局部重确认与高危护栏**：实质改 `AC` 或核心契约时仅重确认受影响部分。**付款、权限、删数据或大范围共享逻辑变更**须先确认范围并另由独立角色验证；**未知外部操作**先查原调用，幂等未明前保持 `blocked` 禁重放。

## 静音连续巡航与抗偏航

`ready_to_implement` 后开启**静音连续巡航**（`T1..Tn → 自验 → 独立对抗验收 → 返修 → verified 收口`）：

### 中途打断白名单
除以下 3 类真阻塞外，**严禁中途询问“是否继续”**：
1. **契约证伪**：实测证明已批规格不可行，须改外部行为或关键架构；
2. **高危副作用**：触及未授权的支付、权限、删数据、发布或非幂等外部写；
3. **外部凭据缺失**：缺仅用户可提供的密钥或远端环境（先跑完其余独立单元后集中反馈）。

### 长跑抗偏航与机械门禁
1. **锚点回读 + 差量单写锁**：每单元完成后**只读回读** `task.md` 与 `AC` 原文防缩水越界；多单元派发前后可用 `verify_feature.py --write-snapshot <snap.json> --repo-root . [--feature-dir <目录>]` 与 `--check-writes --repo-root . --since <snap.json> --allow <写集...>` 拦截越界改动与控制面篡改。
2. **子上下文隔离**：正交写集派发干净子上下文，主会话唯一单写 `task.md`。
3. **2～3 次盲修熔断**：同一故障连续 2～3 次修复无新根因证据立即停手，重核调用链与契约。
4. **`--phase verified` 收口锁**：全新独立 `testing` 会话跑通 `AC` 与反例后，主会话回写 `task.md` 为 `verified` **必须跑通 `verify_feature.py --feature-dir <目录> --phase verified`（`exit 0`）方可交付**。

## 实施与完成门槛

| 检查点 | 准入/完成条件 |
| --- | --- |
| **Spec Gate** | 根本矛盾、`AC`、删减取舍、唯一写入者、契约签名与 `T1..Tn` 明确；异体四项审查通过；`--phase spec-gate` 通过；用户已批（`ready_to_implement`） |
| **单元完成** | 行为/结构检查通过，已只读回读 `AC` 且写集无越界 |
| **整体完成** | 主链路与最高风险反例经全新独立会话实跑通过，主会话回写 `verified` 后跑通 `--phase verified` |

## 契约先行与分层验证

- **业务与脚本代码（`Contract-First` + TDD）**：多模块/多单元先落接口签名、异常契约与失败测试（核实真实 `RED`），再最小实现至 `GREEN`；不适用时说明替代验证。
- **文档、规则与配置（`SDD` + 纯结构/拓扑门禁）**：机械门禁仅验确定性结构（Schema、真实文件与 GFM `#标题锚点`、格式红线、体积上限），严禁跨文件自然语言措辞快照。
- **基础事实推导**：排障回到真实数据流与状态唯一写入者推导首个破坏不变量的根因；未实跑禁报通过。
