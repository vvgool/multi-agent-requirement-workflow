# 名称、续改和修订

按名称匹配、收到续改或准备切版时读取本文。

1. 匹配名称及目标项目。名称支持中文和空格；拒绝空名称、路径分隔符、控制字符、`.`、`..`，核对规范化或大小写冲突和符号链接路径。目录冲突时不覆盖。名称相同而意图不明时先问是续改还是独立需求。
2. 新需求创建唯一 feature_id、名称目录和 v1/input.md，按状态模板初始化并立即回读，使用 [布局 2 与需求入口](output-layout.md)，仅生成当下所需文件。独立同名需求需用户可区分的名称，记录关联 ID。
3. 当前版开发/测试内修复已批准范围的问题，留在当前版本并新增 run；新增功能、修改规则、调整验收标准或修改已提交评审的范围，建立 vN+1。
4. 完成后的优化或缺陷修复均建立新版，旧 completed、审批和证据不变。draft 内整理文稿不单独升版。
5. 有活动任务时先暂停后续派发，等待已结束或有真实取消证据；无法核实时阻塞。不得边切版边让旧任务写目标项目。
6. 切版先保存 vN/status.snapshot.yaml，未完成旧版注明 superseded_by 和未完成原因，不改成 completed。读取旧版有效文档配置，为新版保存 documents.yaml，显式保留 provider、正文/参考来源、access 和飞书策略。每个本地来源固定 source_revision：已配置则保留，否则填旧版 N；按该来源修订定位 path 并重新核验实际内容，不能仅复制相对路径让其指向新目录内不存在的文件。用户明确换源时记录原文、旧新来源及差异。新版保留来源身份，但不把旧快照当作最新读取；无法核实来源则新版 draft/blocked，不回退 local，也不派发产品。
7. Issue 绑定、授权及记录索引属于需求级关联，切版按 [Issue 规则](issue-tracking.md) 保留，不清零为未选择，也不转移旧事件目标；新版仍不继承业务审批。准备新版 input.md 和差异，记录继承的文档策略及新读取来源证据，再更新根版本及 draft/idle（来源阻塞时为 blocked）。新版设置 layout_version=2，旧版布局保留于快照；清空新版审批、待审和 active_run，重置尝试次数；历史记录保留。当前工作空间策略若有变化，重新合并并展示差异，不静默替换来源或扩大权限。
8. 残留新版目录视为未完成切版，恢复时先核对，不能再次创建覆盖。首版不支持并行版本分支。新版状态生效后更新需求 README 指向新版已存在的成果，不能继续把旧版通过报告展示为新版交付。

改名只在无活动任务时进行，先核对目标冲突，保留内部 ID 与相对产物路径，更新 title 并留事件。恢复时核对 ID，旧路径不存在时按 ID 查找，重复 ID 阻塞。工作空间与需求根目录迁移需用户明确要求，不因配置变更自动执行。
