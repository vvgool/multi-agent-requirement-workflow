# 主动路由与按需协作

主会话收到请求后先读相关代码、配置与规则，依**不确定性与耦合度**选路径（不让用户自选模式，不按行数切分）。只读问答不建事项文档。

## 判断维度

| 维度 | 核实事实 | 路由动作 |
| --- | --- | --- |
| 工作性质 | 小修、新功能、探索原型、排障或续改 | 选直通、`Spec Gate`、受控 `Spike`、诊断或原事项 Delta 续改 |
| 确定性 | 根本矛盾、UI 体感与 `AC` 是否清晰 | 有业务分叉合并轻澄清；UI/技术高度未知走隔离 `Spike` |
| 模块契约 | 跨模块依赖、数据唯一写入者与接口边界 | 跨模块耦合贯通起草 `spec.md` 并后台过异体四项审查 |
| 副作用与风险 | 持久化、并发、幂等、支付/权限/删数据 | 明确异常优先级与未知外部写防重放；高危变更先确认范围并独立验证 |

## 路径选择

既有契约内明确局部小修 `0` 门禁直通；需对齐事项后台过完审查与门禁后仅发起 **1 次 `Spec Gate`**。

| 路径 | 适用条件与推进方式 | 文档与验证 |
| --- | --- | --- |
| **明确局部修改** | 目标、方案、边界明确且低风险：定位 → 最小修改 → 相关回归 → 简短返回 | 零建档、零派发 |
| **常规需求** | 局部行为变更：查代码（合并轻澄清）→ `Spec Gate` → 实施 → 收口门禁 | 对话短稿或仅 `task.md`（过 `verify_feature.py`） |
| **复杂需求** | 跨模块数据/接口/状态契约：**贯通起草 `spec.md`（§1+§2）** → 异体四项审查 + `--phase spec-gate` → `Spec Gate` → 静音巡航 → 独立反例验收 + `--phase verified` | 按 [文档分工](documents.md#按复杂度选择文档) 维护三文档，满足 [完成门槛](execution-contract.md#实施与完成门槛) |
| **受控 `Spike`** | UI/技术选型需先看原型定 `AC`：显式隔离写集交最小原型 → 转 `Spec Gate` 补正式契约 | 禁触高危/非幂等写，禁标纯原型为 `verified` |
| **Bug/异常** | 偏离预期：调用链取证 → 复现 RED → 根因最小修复 GREEN → 回归 | 改业务预期或跨模块契约时补 `Spec Gate` |

状态性设计（持久化、并发、事务清理、权限转换或跨入口契约）在 `Spec Gate` 前必过异体四项审查，文件少不免审。

## 专长与按需派发

**合一贯通起草、异体独立审查**：意图清晰时由主会话或单个 `development` 子角色一次性贯通产出 `spec.md`，仅派 **1 个**未参与起草的独立 `testing` 会话做四项审查（禁串行拉起 `product → development → testing`）；仅重大业务分叉、超大模糊范围（`pending_req_approval`）或复杂领域状态时专派 `product`。审查与验收必由独立上下文承担（见 [宿主适配](host-adapters.md#业务派发与降级路径) 与 [最小派发](handoff.md)）。

## 路径切换

- **局部/探索转规格**：发现跨模块冲突或 `Spike` 收敛后，补 `spec.md`、异体审查与 `--phase spec-gate` 再发起 `Spec Gate`，不重问已决项。
- **Bug 转契约变更**：需改模块契约或外部行为时仅对受影响规格请求确认。
- **同事项续改**：按 [Delta 差量规范](documents.md#delta-差量续改与归档) 就地更新，禁建 `v2/v3` 目录。
