# 主动路由与按需协作

主会话对流程选择负责。收到请求后先读直接相关的代码、配置与规则，依事实选路径，不让用户自选模式，也不按代码行数机械分类。只读问答不创建事项文档。

## 判断维度

| 维度 | 核实事实 | 路由动作 |
| --- | --- | --- |
| 工作性质 | 局部修复、功能变更、异常排查或续改 | 选择直通、需求对齐、诊断或原事项 Delta 续改 |
| 业务确定性 | 根本矛盾、规则、可观察状态与 AC 是否明确 | 缺关键业务决策时先读代码，一次性合并提问 |
| 模块与契约 | 跨模块依赖、数据唯一写入者与接口边界 | 跨模块或多规则耦合时进入独立模块契约设计 |
| 状态与副作用 | 持久化、并发、事务清理、幂等、外部写 | 明确异常优先级、幂等保护与失败恢复 |
| 风险与可逆性 | 支付、权限、删数据、大范围共享逻辑变更 | 执行前确认范围，完成后安排独立角色验证 |

## 路径选择

首次修改前先核对上述事实。存在未决业务规则、需新定义可观察状态或跨服务契约时，暂停依赖实现并给出代码事实与合并待确认项；既有契约内的明确局部低风险小修直接完成。

| 路径 | 适用条件与推进方式 | 文档与验证要求 |
| --- | --- | --- |
| **明确局部修改** | 目标、方案、影响明确且低风险：定位 → 最小修改 → 相关回归 → 简短返回 | 零建档、零派发，不跑无关全量测试 |
| **一般需求** | 局部业务决策但边界清晰：合并澄清 → `STOP 1` 需求确认 → `STOP 2` 简要设计确认 → 实施 → 自验 | 对话短稿；跨会话跟踪时仅维护 `task.md` |
| **复杂需求** | 多组业务规则、跨模块数据/接口/状态契约或分批交付：PRD → 模块设计 → 实施前四项审查 → 两次确认 → 静音巡航 → 独立对抗验收 | 按 [文档分工](documents.md#按复杂度选择文档) 维护文档，满足 [完成门槛](execution-contract.md#实施与完成门槛) |
| **Bug/技术异常** | 偏离预期或构建/测试失败：调用链取证 → 复现 → 根因推导 → 最小修复 → 回归 | 原因未知先同角色诊断；改预期或契约时补对应确认 |

状态性设计（持久化、并发、事务清理、权限转换或跨入口契约）在设计确认前必须核查审查适用性；多组规则共同决定一致性或恢复时走复杂需求并完成实施前独立审查，单一服务或改动文件少不能作为免审依据。

## 专长与独立性

角色代表专业职责而非固定流水线：产品负责澄清与可判定 AC，开发负责模块契约、TDD 与技术审查，Bug 负责调用链诊断修复，测试负责实施前四项对齐检查与实施后独立对抗验收。独立审查与最终独立验收必须由**未参与该稿起草或代码实现的独立上下文**承担（见 [宿主适配](host-adapters.md#业务派发与降级路径) 与 [最小派发](handoff.md)）。

## 路径切换

- **局部转复杂**：发现跨模块契约或持久状态冲突时，凭新证据补受影响设计与审查，不重问已确认项。
- **Bug 转设计**：根因需改模块契约时复用明确需求，仅对受影响技术设计请求确认。
- **同事项续改**：按 [Delta 差量规范](documents.md#delta-差量续改与归档) 就地更新，不建 `v2/v3` 目录；仅目标独立时新建事项。
