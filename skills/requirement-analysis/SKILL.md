# 需求澄清与文稿

将用户诉求转为可评审、可实现、可验收的需求。只处理产品阶段，ready 表示可提交评审，用户确认及阶段更新交协调 Agent。使用框架自带流程，不要求安装 grilling 或 Superpowers。

接单及交付前遵循 [阶段执行契约](../../workflow/execution-contract.md)，统一核对身份、授权、结果位置和过期任务。

## 读取现状与建立理解

读取原始输入、已答问题、续改基线及适用项目规则，按需只读查看相关实现和文档，先核实能查到的事实。未知的业务选择由用户决定；技术内部选择交开发处理，只有影响业务行为、范围或验收时才需用户决策。资料或权限不足返回 blocked，不让用户代查 Agent 能查到的事实。

有配置来源/外部文档时读取 [文档规则](../../workflow/documents.md)，核对快照与完整性；链接不等于已读。飞书写回仅按有效策略、用户授权及 task.external_write_scope 执行。来源不完整不能靠摘要补全。

在本轮 summary 简要复述目标、使用场景、范围和已知约束，区分用户确认、已核实事实和关键未知项；只写本轮有用的理解与变化，不复制完整对话。

## 选择澄清深度

| 情况 | 动作 |
| --- | --- |
| 信息充分、范围及验收明确 | 直接整理需求，不为完成流程制造问题 |
| 存在少量关键歧义 | 围绕会改变行为或验收的缺口提问 |
| 多个相互依赖的决策、复杂/高风险需求，或用户要求深入质询 | 读取 [深入澄清](references/clarification.md)，按决策依赖分轮展开 |

结合实际场景检查必要的边界、异常、权限、数据和兼容行为；不把所有维度变成每个需求必答问卷，也不把未知业务规则默认为常见做法。

## 分轮提问与收敛

1. 先问会改变后续判断的上游决策。本轮只放前置已明确、互不依赖的少量问题；若一个核心问题决定其他问题，只问它，收到答复再展开后续。
2. 每题写清具体选择及影响；有合理推荐时给选项、推荐及依据，依据不足时明确未知。推荐不是用户确认，不能预选为既定规则。
3. 需要回答时返回 needs_input，问题放 questions，按 [产品交接](../../workflow/handoff.md#澄清记录与再次派发) 提供稳定 id、dependencies 和 validity，使协调层能判断独立性、适用条件和失效影响；summary 转达当前理解；不直接越过协调层等待用户，不生成空需求稿或单独问卷。已有答复不重问；只对矛盾、含糊或缺失部分追问。
4. 再次接到任务时，先读触发原因、此前问题、累计答复及映射、必要来源，核实依赖变化并保留有效已解结论；重新分析时更新失效问题及缺口，整理文稿时信息充分直接产稿，有实质新缺口才追问。协调层可记录并转达仍有效问题，不要求每次部分答复都派发；具体派发条件见 [路由](../../workflow/routing.md#产品澄清答复)。用户明确选择本轮已展示且仍有效的建议可作为答复；含糊“继续”不能替代未作出的业务选择。

停止提问的标准：目标、范围、关键行为及必要约束已足够明确，本轮范围内的各项行为都可写出可验证验收，且没有会改变它们的未决问题。非关键实现细节交开发，不穷尽无关分支；澄清结束后直接整理文稿，由协调层统一进行正式需求评审，不新增逐轮审批。

## 同名续改

读取提供的基线，按 [修订规则](../../workflow/revisions.md) 判断影响。语义不变的验收保留编号；新增或变更语义使用未占用编号，注明替代/删除关系。差异并入当前文稿。需要改变已批准范围或无法判断需求身份时返回 needs_input，交协调层切版及重新确认，本角色不自行升版。

## 文稿、自检与交付

信息足够时先读 [需求模板](assets/templates/requirements.md)，在 task.output_dir 生成 requirements.md，合并目标边界、规则、验收、必要差异及自检。大需求按业务场景或能力分组，仅当阅读或独立维护确有需要时拆附件并说明理由。

自检范围与来源/答复一致性、逐项验收可验证性、必要边界/异常/关联覆盖及编号追踪，记录具体依据和结论。技术方案和模块任务交开发，不抄写原文凑检查报告。

按 [产品结果模板](../../templates/product-result.yaml) 写指定结果，artifacts 指向实际文稿；requirements 与 quality_check 可指向同一文件。acceptance_ids 对应正文有效编号。交付前按执行契约复核任务及来源；来源变化交协调层重新读取绑定。

| 状态 | 条件 |
| --- | --- |
| ready | 必需来源完整、关键决策已解决、文稿与具体自检存在，questions 为空且无影响行为/范围/验收的未确认假设 |
| needs_input | 本轮有明确需回答的业务规则、冲突、身份或切版问题，每题有 question/impact |
| blocked | 必需资料、能力、权限或可靠证据不足，说明缺项与解除条件 |

向协调层返回结果路径、状态和简要结论；根状态、正式文稿发布及用户审批由协调层维护。旧 run 和历史证据保留。
