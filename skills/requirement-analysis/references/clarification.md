# 复杂事项的产品规格设计

复杂事项起草 `spec.md` §1 或 Delta 续改时读取，使未参与对话的实施者与独立验收者仅凭 `spec.md` 即可无歧义实现与验收。

## 从问题到可判定规格

1. **穿透 XY 问题与代码取证**：先读相关代码、配置与测试，剥离口述**表面解法**追问**根本矛盾**与硬约束；写清痛点、预期变化与非目标（Non-Goals），禁把未证假设当事实。
2. **概念与状态边界**：多角色、持久状态或并发幂等按 [轻量领域建模](domain-modeling.md) 明确核心术语、合法状态转换、唯一修改方与不变量。
3. **流程与异常兜底**：用 Mermaid `flowchart` 表达触发条件、分支与失败/重复提交/无权限的可观察结果。
4. **一次性合并澄清**：可逆细节给推荐默认值，**影响范围或验收的未决分叉一次性合并列入 `task.md` 的 `## 本次请确认`**（标明受影响 `F/AC`，禁拆轮追问）。
5. **稳定编号闭环**：赋予稳定 `F-01`… / `AC-01`… 编号，确保不变量、关键异常与高危边界均映射可判定 `AC`。

## 起草内省与门禁交接

送审前内省（不在文档留自查填空栏）：目标与非目标是否直指根本矛盾？每项 `F/AC` 是否可判定且零占位符？`spec.md` 禁放可变状态头（状态与批准唯一归 `task.md`，见 [人工确认](../../../workflow/execution-contract.md#人工确认) 与 [实施与完成门槛](../../../workflow/execution-contract.md#实施与完成门槛)）。
