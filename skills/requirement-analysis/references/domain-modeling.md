# 需求阶段的轻量领域建模

多角色权限、持久状态、并发幂等或失败恢复共同决定行为时按需读取，直接并入 `spec.md` §1，不为小修单建文档。

## 最小领域快照

| 维度 | 核心问题 | 最小表达 |
| --- | --- | --- |
| 角色与边界 | 谁发起、谁可见、与哪套外部系统交互？ | 角色与信任边界列表 |
| 核心概念 | 哪些名词不可混用？唯一标识与生命周期？ | 紧凑术语表（含禁混称） |
| 状态与不变量 | 哪些状态转换合法？何条件须恒成立？ | `stateDiagram-v2` + 不变量 |
| 动作与结果 | 成功、拒绝、重复提交与结果未知时呈现什么？ | 动作—结果对照 |

## 建模与事实分类规则

1. **忠于业务原词**：提取用户原话与现有术语，易混概念写可判定定义及反例；底层表/类名归 `spec.md` §2。
2. **不变量绑 AC**：每条业务不变量直接体现在对应 `F-xx` 与 `AC-xx`。
3. **事实、建议与待决分离**：已核实事实注明代码或原话依据，整体按 [人工确认](../../../workflow/execution-contract.md#人工确认) 经 `Spec Gate` 获批；可逆建议注回退方式；必答未决合并入 `task.md` `## 本次请确认`，禁以默认值冒充批准。
