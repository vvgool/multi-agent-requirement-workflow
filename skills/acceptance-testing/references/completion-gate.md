# 完成前证据与对抗验收门槛

用于标 `verified`、回写 `task.md` 并交付前的独立核查与机械关门。明确局部小修做针对性回归，不套复杂报告仪式。

## 1. 规格对齐、批准时序与单写边界

- **无缩水无扩权**：核对已批 `spec.md`（§1 `F/AC` 与 §2 `Contract-First` 契约）及实际改动（`git status` / `git diff` 或 [verify_feature.py](../scripts/verify_feature.py) `--check-writes`），确认无遗漏 `AC`、无私自放宽、无越界写入或残留字节码。
- **门禁合规**：按 [人工确认](../../../workflow/execution-contract.md#人工确认) 核实真实 `Spec Gate` 批准记录；实质偏离已获局部重确认。

## 2. 真实运行与强制对抗反例

- **亲自运行正向与回归**：亲自执行主流程及受影响回归命令，开发自验或静态阅读不替代独立运行证据。
- **至少 1 个最高风险反例**：针对最高风险边界（非法/残缺输入、空值越界、重复并发、状态篡改、结构/锚点破坏或权限拦截）构造并实跑至少 1 个破坏性反例，记录命令、退出码与输出（纯静态文案注明无适用运行反例及原因）。
- **分层验证真实性**：代码核实 `RED → GREEN`（事后补测如实标注）；文档/规则核实纯结构/拓扑门禁零快照耦合。

## 3. 环境披露、内部自闭环与机械关门

- **环境披露与防重放**：区分本地静态、沙箱实测、宿主集成与生产环境；未知外部写核实已查原调用且未重放。
- **内部返修与收口必检**：按 [静音连续巡航与抗偏航](../../../workflow/execution-contract.md#静音连续巡航与抗偏航)，非白名单缺陷交主会话内部修复复验；主会话将 `task.md` 回写 `verified` 后，**必跑通 `verify_feature.py --feature-dir <目录> --phase verified`**。

## 4. 标准结论枚举

- **`通过`**：全部适用 `AC` 与反例均有本轮真实运行证据，无未决缺陷。
- **`有条件通过`**：核心交付达标，仅存明确披露且不违背批准条件的外部环境限制。
- **`未完成`**：存在未跑或未过的必验 `AC`、反例缺陷或必需复验。
- **`阻塞`**：缺仅用户可提供的授权、凭据或远端回读条件。
