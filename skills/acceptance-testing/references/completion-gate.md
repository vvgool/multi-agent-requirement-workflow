# 完成前证据门槛

本清单用于在报告“完成”、勾选复杂事项或关闭必需验收前做最后一次范围核对。它补充执行约定，不新增审批、角色、任务账本或发布步骤；一次性局部低风险小修只做与风险相称的相关检查。

## 逐项核对

### 范围和身份

- 当前交付对象、代码/文档基线、事项和允许范围明确且彼此一致。
- 需求、设计、实施任务与验收项能逐项对应；未决假设、排除范围和后续工作有记录。
- 检查的是当前内容；修复、续改或重试后重新核对受影响范围，不沿用旧结果。

### 行为和证据

- 首个核心用户旅程及受影响旧行为已按真实输入验证。
- 关键正常、异常、权限、状态、边界、并发/幂等/持久化场景按适用范围执行。
- 适用 TDD 时，有本次行为对应的真实 RED 原因、GREEN 结果和相关回归；只有事后测试时明确标为回归，不倒推 TDD。
- 开发自验、代码阅读、静态检查和独立验收分开表述；必需独立验收未执行或失败时不得报整体完成。

### 环境和外部状态

- 分别标明源码/静态、本地运行、设备/模拟器、宿主集成和生产结果，缺失环境不算通过。
- 活动调用、待处理输入、失败或未知外部结果已查询并记录；未知结果不重放，不用“没有报错”替代回执。
- 真实发布、部署、消费者安装或远程关闭只有在本次范围明确要求且有对应回读证据时才判定；未要求时也要披露实际未执行。

### 文档和收口

- `task.md` 仅勾选已满足完成条件的任务；必需子任务、集成检查和复验未完成时保持待办。
- 验证文档记录实际命令/操作、结果、证据位置、限制和重验条件，未执行项不写通过。
- 仍有影响本次必需交付的缺陷、冲突、未知或范围遗漏时，结论为未完成或阻塞，并写明解除条件。只有不影响本次必需交付的范围外限制才可使用有条件通过。

## 结论格式

使用以下四种之一：

- **通过**：适用门槛均有证据，无影响交付的未决项。
- **有条件通过**：当前范围可交付，但明确列出的范围外或环境限制不影响本次条件；不得省略限制。
- **未完成**：至少一个必需门槛未执行或未通过。
- **阻塞**：缺少必要授权、环境、身份或外部回读，无法继续判断。

“测试全绿”“开发者确认”“文档齐全”单独都不能替代上述结论。
