# 完成前证据与对抗验收门槛

本清单用于在标记事项 `verified`、勾选 `task.md` 最终验收项并向用户交付前做独立收口核查。局部明确小修做与风险相称的针对性检查，不套用复杂报告仪式。

## 1. 规格对齐与批准时序核查

- **无缩水无扩权**：逐条核对已批准 `spec.md`（`§1` `F/AC` 与 `§2` `Contract-First` 契约）及实际代码改动（`git status` / `git diff`），确认无遗漏 `AC`、无私自放宽判定条件、无违反 Non-Goals 的扩权改动或残留字节码。
- **门禁合规**：按 [人工确认](../../../workflow/execution-contract.md#人工确认) 核实 `task.md` 中真实 `Spec Gate` 用户批准记录；实质偏离已获局部重确认，契约内常规工程细节不重审。

## 2. 真实运行与强制对抗反例

- **亲自运行正向与回归链路**：用真实输入亲自执行主流程及受影响回归命令，开发自验或静态阅读不能替代独立运行证据。
- **至少 1 个最高风险对抗反例**：针对本次改动的最高风险边界（非法/残缺输入、空值越界、重复并发请求、状态篡改、结构/锚点破坏或权限拦截）构造并实际运行至少 1 个破坏性反例，记录真实命令、退出码与拦截输出（纯静态文案无运行或结构校验行为时注明“无适用运行反例”及原因）。
- **分层验证真实性**：代码变更核实 `RED → GREEN` 记录（事后补测如实标为回归验证）；文档/规则变更核实纯结构/拓扑门禁零快照耦合。

## 3. 环境、外部状态与内部自闭环

- **环境诚实披露**：区分源码静态门禁、本地沙箱实测、宿主集成与生产环境；未执行环境如实标明限制。
- **未知外部状态防重放**：存在超时或结果未知的外部写操作时，核实已先查原调用且未盲目重放。
- **内部返修闭环**：按 [静音连续巡航与抗偏航](../../../workflow/execution-contract.md#静音连续巡航与抗偏航)，发现非白名单实现缺陷时直接返回主会话在内部修复与复验，全部达标后再一次性交付用户。

## 4. 标准结论枚举（四选一）

- **`通过`**：全部适用 `AC` 与对抗反例均有本轮真实运行证据，无未决缺陷。
- **`有条件通过`**：核心交付全部达标，仅存在明确披露且不影响本次批准条件的外部环境限制。
- **`未完成`**：存在未执行或未通过的必验 `AC`、反例缺陷或必需复验。
- **`阻塞`**：缺少仅用户可提供的授权、外部凭据或远端回读条件。
