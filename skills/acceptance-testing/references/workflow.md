# 实施前审查与独立验收

完成门槛见 [执行约定](../../../workflow/execution-contract.md#实施与完成门槛)，本页说明测试方法。审查和实际运行分别报告，不把开发自验当成本角色独立验收。

## 实施前可验收性审查

读取相关PRD、设计及计划，核对核心用户旅程、正常/异常/权限及兼容预期，检查功能和验收是否有任务承接、检查方法是否可执行、集成验证是否有人负责。原规则不清时提出具体待决，不擅自发明预期。技术接口、架构与数据边界由协调者安排独立开发专长审查。

审查返回对象与依据、问题位置、触发条件及影响、严重程度、处理要求、未检查范围和结论（可继续／修正后复审／阻塞）。只反馈可执行问题；原写入者修订，同一文件不并写。不为每轮审查另建文件。

## 实施后独立验证

1. 核对实际对象及环境，按需求验收项检查真实行为，不只看模块各自通过。覆盖首个闭环、跨模块集成、关键异常和受影响旧行为。
2. 检查 [测试先行](../../../workflow/test-first.md) 证据：失败是否因目标行为而非环境导致，是否对应本次修改，是否有通过及回归结果。重新运行当前检查只能证明当前结果，不能证明历史执行顺序；缺证据明确未证明TDD。
3. 区分源码阅读、本地运行、设备/宿主和生产结果。缺环境列出阻塞和替代检查，不把本地结果扩大为真实环境通过。
4. 对发现记录可复现输入、预期来源、实际结果及影响；修复后核对改动并重验受影响范围，保留原失败和新结果。

## 最终收口

在把复杂事项标为整体完成、把最终验收写成通过或提交关闭摘要前，读取 [完成前证据门槛](completion-gate.md)，逐项核对当前基线、适用行为、TDD/回归、独立验收、环境层级、未知外部状态和未决项。该核对是证据检查，不是新增审批；小修只执行与风险相称的条目。若必需项未执行或当前内容已变化，保留未完成/阻塞并写明重验条件。

返回实际范围、命令/操作、结果、证据和限制，由原文档写入者合并。必需验收未完成时保留待办；不修改业务源码、不自行派发其他角色、不强制机器交付或单独报告。
