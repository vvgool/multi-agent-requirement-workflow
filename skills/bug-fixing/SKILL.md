# 诊断修复

遵循目标项目规则及 [执行约定](../../workflow/execution-contract.md)。一次性小修在当前会话直接完成，无需先建文档或原生任务；确需持久跟踪才维护一个协调入口，确需委派才用原生任务；不创建机器业务账本、逐轮快照或版本目录。旧任务回原锁定包，不以本 Skill 解释旧任务的权限。共享文档单写，需要长期保留的结果由文档写入者合并。

读取症状、预期、相关实际代码和已有失败证据。一次性、局部低风险且目标明确的小修直接定位→最小修复→相关回归→简短返回，不先建文档、清单、计划或派其他角色。原因不清时先由同一角色复现并沿调用链定位，不自动进入完整阶段链，不预设结论，不按行数/耗时分类。

范围有分歧、涉及付款/权限/数据删除/大范围共享逻辑变更时，先确认具体范围并安排独立验证；不对所有Bug强制边界报告和评审。其他情况直接修复并做相关自验；已有文档需要时合并结果，跨会话恢复、交接或多步持久跟踪才补文档。失败与重验事实如实表述。开发后的补充、测试失败后的修复及完成后的再次修复均沿用原入口，不新建修订目录。

只改与缺陷相关内容，选择能够判断行为的相关现有检查，不默认运行全量测试套件，不为凑证据新增无意义测试，完整日志留已有位置，对话中只展示关键差异。外部结果未知先查询原调用，不重放。无新证据反复失败时停止，说明已试方法和解除条件。必要交接按 [Bug约定](../../workflow/bugfix.md)。

仅在创建或更新人读文档时读取 [格式规范](../../workflow/documents.md#人读文档格式)。复杂根因确需独立说明时读取 [缺陷补充模板](assets/templates/bug-report.md)，具体分歧或风险确需单独展示时读取 [范围模板](assets/templates/bug-boundary.md)；普通小修不生成报告。
