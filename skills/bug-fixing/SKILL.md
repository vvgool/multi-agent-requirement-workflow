# 诊断修复

遵循目标项目规则及 [执行约定](../../workflow/execution-contract.md)。一次性小修在当前会话直接完成，无需先建文档或原生任务；确需持久跟踪才维护一份事项文档，确需委派才用原生任务；不创建机器业务账本、逐轮快照或版本目录。旧任务回原锁定包，不以本Skill解释旧权限。共享文档单写，必要持久结果由文档写入者合并。

读取症状、预期、相关实际代码和已有失败证据。一次性、局部低风险且目标明确的小修直接定位→最小修复→相关回归→简短返回，不先建文档、清单、计划或派其他角色。原因不清时先由同一角色复现并沿调用链定位，不自动进入完整阶段链，不预设结论，不按行数/耗时分类。

范围有分歧、涉及付款/权限/数据删除/大范围共享逻辑变更时，先确认具体范围并安排独立验证；不对所有Bug强制边界报告和评审。其他情况直接修复并做相关自验；已有文档需要时合并结果，跨会话恢复、交接或多步持久跟踪才补文档。失败与重验事实如实表述。开发后补充、测试失败、完成后再修都沿用原入口，不新修订。

只改与缺陷相关内容，选择能够判断行为的相关现有检查，不默认全量suite，不为凑证据新增无意义测试，完整日志留已有位置，对话只读关键差异。外部结果未知先查询原调用，不重放。无新证据反复失败时停止，说明已试方法和解除条件。必要交接按 [Bug约定](../../workflow/bugfix.md)。
