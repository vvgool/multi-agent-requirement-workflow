# 复杂事项的契约设计与单元拆分

复杂事项起草 `spec.md` 第二部分、拆分实施单元或 Delta 续改前读取。缺少关键业务决策分叉时先交主会话按 [人工确认](../../../workflow/execution-contract.md#人工确认) 一次性合并澄清，不靠猜测硬写架构。

## 1. 先定模块边界与契约，再拆实施单元

1. **调用链取证与复用优先**：沿真实代码入口识别可复用模块、改动点与外部 SDK/平台约束；未证实的外部能力先做只读核查。
2. **第一性原理（先删减、再下沉、后新增）**：动笔前先质疑既有假设——优先删减无需存在的兼容层、重复文档或中间状态，将校验/同步等**机械约束下沉**给确定性代码、类型或结构校验脚本，最后对关键架构取舍集中比较利弊。
3. **职责正交与 Contract-First 签名**：用 Mermaid 架构图（`flowchart` / `sequenceDiagram`）标清模块边界与可变状态的唯一写入者，并在 `spec.md` 第二部分前置跨模块函数签名、数据结构与异常契约。
4. **表示范围与复合失败契约**：
   - **值域与精度贯通**：沿 `输入 → 转换 → 存储 → 输出` 核对值域、精度与单位，防止底层默认限制无声截断契约。
   - **主操作与清理复合异常**：涉及事务、锁或资源释放时，明确“主操作失败且清理失败”与“主操作成功但清理失败”的异常优先级及一致性结果；外部操作结果未知时先查原调用，禁止自动重放。

## 2. 按可独立验证的行为拆解单元（T1..Tn）

- **契约与主干优先**：多单元协作优先在首单元固定共享接口契约与失败测试，打通高风险端到端主干后再叠加分支。
- **单元自包含与正交写集**：每个实施单元（`T1..Tn`，与 `task.md` 严格同号，在 `spec.md` 切分表中不放复选框，由主会话据此单写 `task.md`）写清关联 `AC`、精确允许写入文件、输入/产出契约、分层验证命令（遵循 [契约先行与分层验证](../../../workflow/execution-contract.md#契约先行与分层验证)）及单元完成后的 `AC` 锚点回读要求。仅接口固定且写集完全正交无交集时允许并行派发。

## 3. 后台独立审查闭环与单次 Spec Gate

起草者按 [文档分工](../../../workflow/documents.md#按复杂度选择文档) 核对 `spec.md` 内 `F/AC → D/Contract → T` 全覆盖且零状态头后，由主会话先在后台安排独立角色执行 [四项规格对齐审查](architecture-review.md)。消除阻断后将 `task.md` 置为 `pending_approval` 向用户发起单次 `Spec Gate`；获真实用户授权（`ready_to_implement`）后进入静音连续巡航实施。
