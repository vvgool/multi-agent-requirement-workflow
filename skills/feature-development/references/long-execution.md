# 长任务与恢复

任务进度只在本次实现计划的原条目勾选或标注；简版及小修复按开发Skill使用 development.md。暂停、模块检查完成或上下文可能丢失时合并更新，阻塞、需重验及必要下一步就地说明，不新建恢复记录、检查点文件或另一套任务状态。精确代码标识、内部路径及原始验证输出按 [执行契约](../../../workflow/execution-contract.md#缓存与证据) 保存，计划只保留可读说明；昂贵或难以重现的检查证据及时保存。

恢复步骤：

1. 重读当前 task、status、批准正文和授权，确认仍是有效任务；过期则报告 stale_task。旧交付 只按当前任务明确列出的资料继承，旧计划不直接当成本轮已完成状态。
2. 读取当前计划、实际代码和验证证据，按 [代码基线契约](../../../workflow/code-baseline.md) 核对实际提交及相关未提交改动。勾选不等于通过证据；缺少可靠证据或代码标识时重新核验，不能凭会话印象补写通过。
3. 证据失效时，在原计划取消受影响任务的完成勾选，注明该任务及下游需重验；核实不受影响的项保留。模块通过但整体验证失败时保留局部证据，修复集成或记录阻塞，不能 ready。
4. 更新原计划，通过相关检查及必要整体自验后交付；不另写恢复进度或复述所有已完成任务。

已有独立检查点和旧格式文稿按索引读取保留；新任务不续建旧进度协议。长任务不表示会话结束后宿主仍会后台运行。
