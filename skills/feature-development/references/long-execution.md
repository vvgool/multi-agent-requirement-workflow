# 长任务与恢复

恢复信息写入本run已有执行记录（无可用记录时才在 outputs 创建一份恢复记录），不固化到 documents：当前位置、当前代码标识、需重验项、阻塞及下一动作；已完成项和证据引用计划/验证记录，不重复维护另一套任务状态。已有恢复信息继续就地维护，避免重复建档。

每个可验证任务完成或暂停前，先在本run执行记录保存证据及可比较的代码标识（实际提交与相关未提交文件摘要，或已存基线链接），即时在该执行记录更新对应模块/任务的进度；计划按执行契约规定的下一次必要更新集中记录，必要时引用共享自验文稿的检查结论。候选文稿由开发单写，更新完成后再通知，内部证据链接留执行记录。恢复记录只写当前位置、需重验范围和下一步，不在多处重复维护即时任务状态或保留“将执行”的过期进度。普通执行中断也适用。

恢复步骤：

1. 重读当前 task、status、批准正文和授权，确认仍是有效任务；过期则报告 stale_task。旧 run 只按当前任务明确列出的资料继承。
2. 读取实际计划/恢复信息和代码，按 [代码基线契约](../../../workflow/code-baseline.md) 比较提交及相关未提交改动或文件摘要。旧记录无可靠标识时重新核验，不能只凭勾选复用结论。
3. 证据失效时标记受影响任务、模块及下游需重验，再继续。模块通过但整体验证失败时保留局部证据，修复集成或记录阻塞，不能 ready。
4. 更新恢复依据和下一动作，通过相关检查及必要整体自验后再交付。

已有独立检查点和旧格式文稿按索引读取，不要求重建或删除。长任务表示可恢复的开发执行，不表示会话结束后宿主仍会后台运行。
