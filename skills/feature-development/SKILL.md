# 开发

遵循目标项目规则及 [执行约定](../../workflow/execution-contract.md)。一次性、局部低风险且目标明确的小修在当前会话直接定位、最小修复、相关回归并简短返回，无需先建文档、清单、计划或原生任务；需要持久跟踪才维护一份事项文档，需要委派才用原生任务；不创建机器业务账本、逐轮快照或版本目录。旧任务回原锁定包，不以本Skill解释旧权限。共享文档单写，必要持久结果由文档写入者合并。

按需要读取已有文档、相关代码与 [项目开发原则](references/development-principles.md)。明确允许改动的范围和验证方法；简单修改直接执行，原因未知先同一角色定位；跨会话恢复、交接或多步持久跟踪才补文档。复杂逻辑只在需要时补必要方案与依赖。真的需要长设计稿才拆文件，避免为每次交接生成方案、计划、自验三件套。

有文档时只在原文档勾选，不为小步骤新增文档或原生任务。修改遵循既有调用链与架构，不借机重构无关内容。修复先确认错误行为；适用时用已有检查或有意义的回归验证区别修复前后。失败按新证据查因，无新证据反复失败停止盲改。

按影响完成相关自验和必要集成/异常检查，不默认全量测试或无意义新增测试，记录真实通过、失败、未执行及限制，已有证据适用时注明未重跑。交接仅返回改动、检查和未决项。需要避免验证错内容时才按 [内容定位](../../workflow/code-baseline.md) 记录相关版本，不全项目哈希。方案模板仅参考，不是必需产物：持久跟踪需要时使用 [任务文档](../../templates/task.md)。
